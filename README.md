# Туристический ассистент (LangGraph)

Агент составляет **культурную программу поездки** по городу и датам: билеты туда-обратно (самолёт, поезд, автобус), музеи и мероприятия, рестораны в пешей доступности от достопримечательностей, городской транспорт и лайфхаки. Данные берутся из **живого веб-поиска** (не из заглушек). Перед планированием — **опросник из 7 вопросов**; поездки и версии программы хранятся в **SQLite**.

## Быстрый старт

### Требования

- Python **3.10+** (работает на 3.9+)
- Ключ **OpenAI API** (через [ProxyAPI](https://proxyapi.ru) или напрямую)

### Установка и запуск

```bash
git clone <url-репозитория>
cd tourist-assistant

python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate

pip install -r requirements.txt

cp .env.example .env
# Отредактируйте .env: OPENAI_API_KEY=...

python main.py
```

В меню:

1. **Новая поездка** — город, даты, вылет, запрос → предпочтения:
   - **первый запуск** — полный опросник (7 вопросов);
   - **если опросник уже проходили** — опрос **не показывается**; используются сохранённые предпочтения. Только по запросу: «Пройти опрос заново?» (по умолчанию — нет).
2. **Продолжить** — выбор сохранённой поездки по `id` → пересборка программы с предпочтениями этой поездки.

Через 1–2 минуты появятся разделы: **Билеты**, **Мероприятия**, **Питание**, **Транспорт**, **Лайфхаки**.

### Тесты (без API)

```bash
python3 -m unittest discover -s tests -v
```

### Переменные окружения

| Переменная | Обязательно | Описание |
|------------|-------------|----------|
| `OPENAI_API_KEY` | Да | Ключ для LLM |
| `PROXY_BASE_URL` | Нет | По умолчанию `https://openai.api.proxyapi.ru/v1` |
| `TAVILY_API_KEY` | Нет | Точнее веб-поиск; без ключа — DuckDuckGo (`ddgs`) |
| `DATABASE_PATH` | Нет | SQLite, по умолчанию `data/trips.db` |

Шаблон: [`.env.example`](.env.example).

## Архитектура

```mermaid
flowchart TB
    CLI[CLI: новая / продолжить]
    Q[Опросник 7 вопросов]
    DB[(SQLite)]
    subgraph graph [LangGraph]
        planner -->|tool_calls| executor
        planner -->|готово| finalize
        executor --> planner
    end
    CLI --> Q
    Q --> DB
    CLI --> graph
    graph --> DB
    finalize --> END
```

| Узел | Роль |
|------|------|
| `planner` | LLM планирует и вызывает инструменты (с учётом предпочтений) |
| `executor` | Выполняет веб-поиск, возвращает `ToolMessage` |
| `finalize` | Собирает структурированную программу (`FinalProgram`) |

**Инструменты (3):**

| Инструмент | Что ищет |
|------------|----------|
| `search_roundtrip_tickets` | Авиа, РЖД/Tutu, автобус |
| `search_culture_events` | Афиша, музеи, выставки (по району) |
| `search_dining_and_transport` | Рестораны (много ссылок) + транспорт |

Запросы к поиску дополняются **`search_context`** из опросника (темп, бюджет, интересы, рейтинг ресторанов, транспорт).

Стек: **LangGraph 0.2+**, **LangChain 0.3**, **ChatOpenAI** (`gpt-4o-mini`), **Pydantic**, **SQLite**, **ddgs** / **Tavily**.

## Проектирование агента

### Какую задачу решает агент?

По городу, датам, предпочтениям (опросник) и городу отправления агент **собирает актуальную информацию из интернета** и формирует **готовую культурную программу**, сохраняя версии в SQLite.

### Кто будет пользоваться агентом?

**Частные путешественники** и **менеджеры поездок** (самостоятельный туризм): один запрос и опросник вместо ручного поиска на Aviasales, Афише и картах; возможность **вернуться к поездке** и пересобрать программу.

### С какими внешними системами и данными работает агент?

| Система | Назначение |
|---------|------------|
| **OpenAI API** (ProxyAPI) | Планирование, tool calling, финальный ответ |
| **SQLite** (`DATABASE_PATH`) | Поездки, предпочтения, профиль пользователя, версии программы |
| **Tavily API** (опционально) | Веб-поиск с ответом-сводкой |
| **DuckDuckGo** (`ddgs`, ru-ru) | Бесплатный веб-поиск по умолчанию |
| **Aviasales / Яндекс.Путешествия** | Ссылки и сниппеты по авиабилетам |
| **РЖД / Tutu.ru** | Поезда |
| **Bus.ru и аналоги** | Автобусы |
| **Афиша / Kassir.ru** | Мероприятия |
| **2GIS / Яндекс.Карты / TripAdvisor** | Рестораны и транспорт |

Прямые партнёрские API этих сервисов **не подключены** — агент находит публичные страницы через поиск.

### Почему нужен именно агент, а не workflow?

- **Нестабильный ввод**: даты и города в свободной форме, опросник и уточнения в запросе.
- **Многошаговый сбор**: какие инструменты вызвать и когда достаточно данных для финала.
- **Синтез из шума**: LLM отбирает факты из `digest`, группирует по районам.
- **Память поездки**: SQLite и «продолжить» без повторного ввода города и дат.

### Сложные и нестандартные ситуации

| Ситуация | Обработка |
|----------|-----------|
| **Пустой или нерелевантный поиск** | Фильтр по категории + fallback; предупреждение в payload |
| **Ошибка поиска / сети** | `ToolMessage` с ошибкой; граф не падает |
| **Prompt-injection во вводе** | `sanitize_and_validate` |
| **Галлюцинации цен** | Промпт: цены только из `digest` |
| **Продолжение без опросника** | Предпочтения из `trip_preferences`; иначе поиск без персонализации |
| **Конфликт категорий** (музей в «Билетах») | Постфильтрация `_SEARCH_FILTERS` |

### Как понять, что агент работает хорошо?

| Критерий | Приемлемый результат |
|----------|----------------------|
| **Полнота программы** | Все 5 разделов; в «Билетах» ✈️ 🚂 🚌 со ссылками |
| **Опора на поиск** | ≥ 6 ресторанов со ссылками из digest; мероприятия по району |
| **Память и воспроизводимость** | `python3 -m unittest discover -s tests` проходит; поездка видна в «Продолжить» |
